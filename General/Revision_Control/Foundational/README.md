# Revision Control Tutorial : Foundational

***Version: AMD Vivado&trade; 2025.2***

## Introduction

This tutorial presents a foundational approach to revision control for **Block Designs (BD)** and **AMD IP cores (XCI)** using TCL scripts. This methodology is highly recommended for most users due to the inherent **migratability** and **readability** of TCL files.

IPs and BDs can be generated by a single human readable TCL file which is easy to track changes in revision control. This workflow significantly simplifies the version control process, making it particularly advantageous for those who do not need to revision control the many files in the generated outputs directories. NOTE: It is not recommended to revision control only the BD or the XCI file without the output products generated. This is due to the BD and XCI files containing hard coded relative path for the .gen directory. The hard coded relative path could point to an unwanted directory depending on where the XCI/BD files reside or how they are read into the Vivado™ build environment. 

Moreover, this methodology integrates seamlessly with the **IP Cache**, which helps improve compile times and enhances productivity. By adopting this methodology, users can focus on the essential elements of their designs while minimizing overhead associated with output management.

The following sections will outline the design flow in both **Project Mode** and **Non-Project Mode**, providing clarity on how to effectively implement this revision control strategy.

## Focus
- This is the basic recommended design flow to revision control for Block Designs and IPs.
- ip.tcl for an IP can be generated with the  ```write_ip_tcl``` command.
- bd.tcl for a BD can be generated with the ```write_bd_tcl``` command.


## Pros 
- Works with Project and Non-Project mode.
- Leaner revision control sources
  - The TCL representation of IP and BD are low in size with very minimal information required to recreate them.
- Move-able across directories 
  - The TCL representation of IP and BD are move-able across directories as this does not have relative references to any other files.
## Cons
- Generation and synthesis of RTL is always necessary as this methodology does not revision control the .dcp and generated RTL files of IP.
- IP and BD must be upgraded when going to a new version of Vivado™.
  - User must upgrade the IP manually when Vivado™ version is upgraded by following the steps:
    - Open the current project in new Vivado™ version.
    - Upgrade the IPs following IP Upgrade methodology.
    - validate the BD 
    - Write out upgraded and validated BD using write_bd_tcl 
    - Write out upgraded IP using write_ip_tcl ( for IPs outside BD)
 
## Launch tutorial
- Execute ```make all``` to launch the project creation in both project mode and non-project mode.

- Execure ``` make project_mode``` to launch the project creation only in project mode.

- Execute ``` make non_project_mode``` to launch the project creation only in project mode.

- Execute ``` make clean``` to clean all generated outputs.

## Design Flow

### Project Mode
- Source the following file to launch  the design creation in Project Mode.
 ``` build_design_from_tcl.tcl ```

- The script does the following functions:
#### Sourcing the ip.tcl to create the IPs

  ```
source ../sources/ip/axi_bram_ctrl_pl_slave_from_pl_master.tcl
source ../sources/ip/axi_bram_ctrl_pl_slave_from_ps.tcl
source ../sources/ip/axis_vio_pl_master_to_ddr.tcl
source ../sources/ip/axis_vio_pl_master_to_pl_slave.tcl
source ../sources/ip/axis_vio_pl_master_to_ps.tcl
source ../sources/ip/axis_MxN_vio.tcl
source ../sources/ip/axi_tg_pl_to_pl.tcl
source ../sources/ip/axi_tg_pl_to_ps.tcl
source ../sources/ip/axi_tg_pl_master_to_ddr.tcl
  ```

#### Sourcing the bd.tcl to create the block diagram
```
source ../sources/bd/bd.tcl
```
### Non-Project Mode
- Source the following file to launch the design creation in non-project mode. This does not create an on-disk project.

``` build_design_non_prj_from_tcl.tcl```
